# 移动端视频首屏无法播放排查

## 现象

移动端 H5 视频「首屏大概率无法播放、滚动后才可见反而能播放」。

复现条件：5 台手机安装**同一个浏览器 APK**（荣耀浏览器，自研内核），**只有 1 台复现**，其余 4 台首屏正常。

## 核心矛盾

首屏与滚动后可见的视频走的是不同渲染路径：

- 首屏视频在页面「初始合成/首次绘制」阶段就渲染并调用 `play()`
- 滚动后才可见的视频，是在页面稳定后、元数据已加载好时才渲染/播放

所以现象只在「首屏失败」说明是**初始化时序问题**，而非 autoplay 策略问题（策略与滚动位置无关）。

## 关键澄清：自研内核 ≠ 全自包含

浏览器即便内核是 APK 自带的，跑视频时仍要调用手机系统底层的组件：

| 环节 | 谁提供 | 是否跟手机有关 |
|---|---|---|
| 硬件视频解码（H.264/H.265） | 系统 MediaCodec / OMX / 芯片厂商解码器 | 是 |
| GPU 渲染 / 纹理分配 | 系统 EGL / OpenGL ES / Vulkan 驱动 | 是 |
| 画面合成上屏 | SurfaceFlinger / HWC 硬件合成器 | 是 |

内核（Chromium 分支）只是调度者，真正硬解和合成靠以上系统/芯片组件。所以「同 APK + 自研内核 + 只有一台复现」完全成立——问题不在内核代码本身，而在**内核视频渲染路径 × 某款芯片驱动/解码器**的兼容性。

## 收窄后的结论

> 荣耀浏览器内核「首屏视频渲染路径」与**某一款 SoC/GPU/解码器驱动**不兼容的兼容性 bug，只在那个机型上触发。

机制：首屏视频在「初始合成阶段」就要创建硬解 surface + 分配 GPU 纹理，某款芯片驱动在该时点失败；滚动后才渲染的视频是「页面稳定后干净地新建」，避开雷区，所以正常。

## 根因（按概率排序）

已排除：autoplay 策略差异、内核代码 bug（同 APK 同内核，5 台一致）。

1. **芯片/GPU 驱动在「初始合成期渲染 video」时失败**——硬件解码 + GPU 纹理分配在首次绘制阶段失败，滚动后才渲染反而正常。
2. **`play()` 在 `readyState < 3`（元数据未就绪）时被调用**，Promise 被 reject；老内核/老驱动可能直接失败。
3. **`preload="auto"` 导致首屏视频与图片/JS 抢初始化资源**；滚动视频通常是懒加载，资源空闲才成功。
4. **懒加载/IntersectionObserver 对「一开始就在视口内」的首屏视频漏处理**（若靠 scroll 事件而非 IO，首屏永不触发）。

## 修复（性价比从高到低）

1. 统一「就绪后再 play + 失败重试」：`readyState >= 3` 才 `play()`，否则监听 `canplay` 再播，`play()` 的 Promise `.catch()` 里重试。
2. 首屏自动播加 `muted playsinline webkit-playsinline preload="auto"`。
3. 首屏视频延迟到 `load` 事件 + `requestAnimationFrame` + `setTimeout(≈100ms)` 后再播，避开初始化竞争。
4. 用 IntersectionObserver（首次回调会对已在视口的元素也触发）替代 scroll 事件判断进入视口。
5. **首屏先用 poster/首帧图占位，等 `loadedmetadata`/`canplay` 后再真正渲染 `<video>`**，避开「首次绘制阶段就渲染 video」这个雷区。
6. 若源是 HEVC/高分辨率，降级为 H.264 baseline 可救部分机型解码失败。

```js
// 就绪后再 play，并失败重试
function safePlay(video) {
  const tryPlay = () => {
    const p = video.play()
    if (p && p.catch) {
      p.catch(() => {
        if (video.readyState < 3) {
          video.addEventListener('canplay', () => video.play(), { once: true })
        }
      })
    }
  }
  if (video.readyState >= 3) tryPlay()
  else video.addEventListener('canplay', tryPlay, { once: true })
}
```

## 排查第一步

对比 5 台手机的**机型 / SoC / Android 版本**，找出故障机与正常机的唯一差异（麒麟/骁龙/天玑，或 Android 版本高低）。故障机临时关硬件加速/硬解，首屏恢复 → 实锤硬解/GPU 路径。
