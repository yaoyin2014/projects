# 瀑布流 H5 页面 · 实施技术方案

> 目标：新建一个可访问的 H5 页面，用卡片组件（图片 + 文字）做响应式瀑布流，支持单/双列切换与无限滚动。

---

## 1. 需求拆解

| # | 需求 | 实现要点 |
|---|------|----------|
| 1 | 可访问路由 | 引入 `vue-router@4`，`/` 重定向到 `/cards`（默认入口），原 SwipeImageList 演示迁到 `/swipe` |
| 2 | 四种高度组件 | 卡片高度 110 / 150 / 230 / 370 px，均含图片 + 文字 |
| 3 | 响应式列数 | 视口宽度 ≤ 600px → 单列；> 600px → 双列 |
| 4 | 双列紧凑 | 双列采用瀑布流（两列高度平衡），间隙收紧 |
| 5 | 分批加载 | 每次加载 10 个组件 |
| 6 | 无限滚动 | 距底部 4 个组件时，自动加载下一批 10 个 |
| 7 | 屏幕翻转 | 横竖屏切换时重新计算列数与重排 |

---

## 2. 技术选型与滚动模型

- **框架**：Vue 3（`<script setup>` 组合式 API），沿用现有 Vite 构建。
- **路由**：`vue-router@4`（需新增依赖，`npm i vue-router@4`）。
- **响应式**：原生 CSS `@media` + `window.matchMedia('(max-width: 600px)')`，不引入 UI 框架。
- **无限滚动**：原生 `IntersectionObserver` + 哨兵元素，无需第三方库。
- **图片**：占位图 `picsum.photos/seed/{id}/{w}/{h}`，`loading="lazy"` + 本地背景色兜底。

### 2.1 关键：滚动容器是「滚动根」，不是内容链

本项目的实际 DOM 层次：

```
body                                  ← 无显式 overflow，视口（documentElement）滚动
└── div#app
    ├── header.topnav                 （sticky 顶栏）
    └── div.cards-page
        ├── div.feed (#wrap)          瀑布流两列 Grid，随内容撑高
        └── div.sentinel              哨兵，始终是内容最底部元素
```

- 内容链总高随卡片追加而增长，**滚动发生在视口（`documentElement`）**——html/body 都没设 overflow。
- 因此所有「视口」「底部」的几何量都锚定真实滚动根，**不硬编码 `window.innerHeight` 或 `body`**。
- `.feed` 那串只是普通内容，不是滚动容器。
- **注意 html/body 的 overflow 提升规则**：当 `html` 的 `overflow` 为 `visible`（默认）时，给 `body` 设 `overflow-y:auto` 会被「提升」到 viewport，`body` 自身 used overflow 变 `visible`，此时真正滚动的是 viewport 而非 body。`!important` 不改变该规则。所以**滚动根必须在运行时探测，不能硬编码**（见 §7.1）——本方案实际探测到 `documentElement`；若部署环境给 body 设了 overflow，则可能是 body。

## 4. 路由方案

`src/router/index.js`：

```js
import { createRouter, createWebHashHistory } from 'vue-router'
import CardsPage from '../views/CardsPage.vue'
import SwipeImageList from '../components/SwipeImageList.vue'

const routes = [
  { path: '/', redirect: '/cards' },                 // 默认进入新页面
  { path: '/cards', component: CardsPage },
  { path: '/swipe', component: SwipeImageList },
]

export default createRouter({ history: createWebHashHistory(), routes })
```

- 选择 `createWebHashHistory`：H5 静态部署/直接打开 `dist/index.html` 时无服务端重写也能访问，避免刷新 404。
- 组件用**静态导入**而非 `() => import()`：直接 `file://` 打开 `dist/index.html` 时，动态导入会拆出独立 chunk、受 CORS 限制加载失败；本项目体积小，单包更稳妥。
- `App.vue` 改为 `<router-view />`，并加两个 `<router-link>`（`/cards` 与 `/swipe`）作为入口，保证「可访问」。

## 5. 卡片组件 `MediaCard.vue`

统一一个组件，通过 `size` 变体决定高度与内部布局：

| size | 高度 | 布局 |
|------|------|------|
| `small`  | 110px | 横向：图左（缩略）文右 |
| `medium` | 150px | 横向：图左（更大）文右 |
| `large`  | 230px | 纵向：图上文下 |
| `xlarge` | 370px | 纵向：大图上文下 |

- Props：单个 `item` 对象 `{ id, size, title, desc, image }`（父级 `v-for` 传 `:item="it"`）。
- 图片 `object-fit: cover`、`width:100%`、`loading="lazy"`。
- 文字区固定结构：标题（单行省略）+ 描述（最多两行省略），**行数必须 clamp 固定**，否则文字换行会让卡片高度漂移。
- **卡片必须显式设 `height: HEIGHT[size]`**（`card--small` 等 class 写死），图片只填满它被分配的那块区域（`object-fit: cover`）。

> 高度 `HEIGHT = { small:110, medium:150, large:230, xlarge:370 }` 指**卡片整体高度**，供 Grid span 与触发距离复用。
> **关键**：Grid 的 `span = HEIGHT + GAP` 和贪心平衡都要求「卡片实际渲染高度 === HEIGHT 常量」**逐像素精确**成立。图片高度已设 px 只说明「图片高度确定」，但卡片 = 图片 + 文字 + padding，仍可能 ≠ HEIGHT。所以别靠内容自然撑高去假设——直接给卡片设显式 `height`，把假设变成硬保证；否则长列表下两列会悄悄错位。

## 6. 响应式布局与瀑布流算法

### 6.1 断点
- `window.matchMedia('(max-width: 600px)')` 的 `change` 是唯一真相源；`resize` 仅作旧浏览器兜底、且只在列数真变时重排（见 §8）。
- `≤ 600px`：单列；`> 600px`：双列。

### 6.2 列平衡纯计算（`useResponsiveColumns.js`，仅用于触发距离，不用于渲染）

渲染交给 CSS Grid（§6.4），这里只保留一份**同样的贪心规则**做纯计算，用于算「较高列最后 4 张」喂给触发距离（§7.2）：

```js
const left = [], right = []
let hLeft = 0, hRight = 0
if (isNarrow) {
  // 单列：全部并入一列，右列为空
  for (const it of items) { left.push(it); hLeft += HEIGHT[it.size] + GAP }
} else {
  // 双列：贪心最短列（与 CSS Grid 稀疏放置同一条规则）
  for (const it of items) {
    if (hLeft <= hRight) { left.push(it); hLeft += HEIGHT[it.size] + GAP }
    else { right.push(it); hRight += HEIGHT[it.size] + GAP }
  }
}
```

- 双列下与 CSS Grid 的稀疏放置是**同一条贪心规则**（见 §6.4），所以 `hLeft/hRight` 与渲染出来的两列高度一致。
- **单列时 `isNarrow` 分支把全部卡并入一列、右列为空**，`triggerDistance` 自动退化为「最后 4 张高度和」（见 §8.1），无需单独分支。
- 高度为已知固定值，故可精确计算，无需 DOM 测量。

### 6.3 样式要点（CSS Grid 瀑布流）
- 双列：`grid-template-columns: repeat(2, 1fr)` + `grid-auto-rows: 2px`，卡片用 `grid-row-end: span N` 占位（细节见 §6.4）。
- 单列：`grid-template-columns: 1fr`。
- 容器最大宽度居中（如 `max-width: 720px`），避免超宽屏拉伸。

### 6.4 渲染结构：单 v-for + CSS Grid（**关键，防漏卡 + 保证紧凑**）

单列/双列**绝不能**用 `v-if` / `v-else` 切换，也**不能**给 key 加 `L-`/`R-` 前缀，更**不要**拆成两个 `v-for`。这些都会让 Vue 在切换或跨列移动时**销毁并重建**卡片元素，导致监听方（IntersectionObserver 等）持有的元素引用失效、漏卡。

正确做法：一个 flat `v-for` + CSS Grid，列数交给 CSS：

```html
<!-- 一个 v-for，key 恒为 item.id；列数由 CSS 切，切换时不触碰卡片 -->
<!-- 此容器即 §2.1 的 #wrap（class .feed 仅用于样式） -->
<div id="wrap" class="feed" :class="{ 'is-single': isNarrow }">
  <MediaCard
    v-for="it in items"
    :key="it.id"
    :item="it"
    :style="{ gridRowEnd: `span ${(HEIGHT[it.size] + GAP) / 2}` }"
  />
</div>
```

```css
.feed {
  display: grid;
  grid-template-columns: repeat(2, 1fr);  /* 双列 */
  grid-auto-rows: 2px;                     /* 2px 基准行（HEIGHT+GAP 均为偶数，见保证 4） */
  grid-auto-flow: row;                     /* 稀疏放置 = 最短列优先 */
  column-gap: 8px;
  align-items: start;                      /* 卡片保持自身高度，不被 stretch 拉满 span */
}
.feed.is-single { grid-template-columns: 1fr; }  /* 单列只改这一行 */
```

> **`align-items: start` 是必须的**：卡片是内容撑高（`height` 若非显式，`align-self` 默认 `stretch` 会把卡片拉到 `HEIGHT+GAP`、吃掉间隙）。同时卡片需显式 `height: HEIGHT[size]`（§5），保证 span 与真实高度逐像素一致。

**这套结构成立的四条保证：**

1. **切换零重建/零移动**：`items`、key、顺序、`grid-row-end` span 在单列与双列里全都一样，只有容器的 `grid-template-columns` 变。Vue 对卡片既不重建也不移动，监听引用全程有效。
2. **紧凑（无洞）是结构保证**：2 列下 Grid 稀疏放置 = 贪心最短列（每张卡放到当前 bottom 更小的列）。列内贴底、列间无需对齐 → 无空隙。前提三条：**恰好 2 列**、**每张卡只占 1 列宽**、**用稀疏 `row` 而非 `dense`**。
3. **追加不移动旧卡（前缀稳定）**：第 k 张卡的位置只由前 k 张的高度决定，追加第 N+1 张不影响前 N 张。旧卡既不换列、也不上下移动，新卡只在较矮列的缺口冒出来。DOM 侧同理——Vue keyed diff 只往末尾 append，旧元素不动、不重建。
4. **2px 基准行（已采用）**：`grid-auto-rows:1px` 会让轨道数 = 列高像素数，超长 feed（几千张）会变重。本方案用 `grid-auto-rows:2px`——四个高度 110/150/230/370 加间隙 8 后公约数为 2，`span = (HEIGHT+GAP)/2` 仍为整数（59/79/119/189），轨道数减半。更长列表可再换 CSS `columns`（零轨道，但变列主序）或虚拟列表。

## 7. 无限滚动（`useInfiniteScroll.js` + `useScrollContainer.js`）

### 7.1 运行时解析真实滚动根（scrollTop 探针）

不硬编码 `root: body`，因为 body 的 overflow 可能被提升到 viewport。用「能不能真的滚」判定：

```js
function isReallyScrolling(el) {
  if (!el || el.scrollHeight <= el.clientHeight) return false
  const before = el.scrollTop
  el.scrollTop = 1
  const moved = el.scrollTop !== before      // 设置成功 = 真的在滚
  el.scrollTop = before
  return moved
}

function resolveScrollRoot(wrapEl) {
  let el = wrapEl?.parentElement
  while (el) {
    if (isReallyScrolling(el)) return el
    el = el.parentElement
  }
  return null                                  // 找不到 → 视口（root: null）
}
```

- 从 `#wrap` 往上走，命中第一个真在滚的祖先（本场景 = `documentElement`，html/body 均未设 overflow）。
- IO 的 `root` 填该元素；返回 `null` 则代表视口滚动（两者对 IntersectionObserver 等价）。

### 7.2 哨兵 + 自适应触发距离

- 状态：`items`（已加载）、`loading`（防重复）、`finished`（是否到底）。
- 每批 `BATCH = 10`。
- **哨兵**：Grid 容器（`#wrap` / `.feed`，同一元素）之后的普通流兄弟节点 `<div class="sentinel">`（**不能**是 grid 容器的子项，否则会被当成一个 grid 项参与放置），始终是内容最底部的元素，随滚动容器滚动。
- **触发距离自适应**：`rootMargin` 底部 = 「较高列最后 4 张卡高度和 + 间隙」（`left/right/hLeft/hRight` 来自 §6.2 的纯计算，与渲染无关），而非固定 `4×370` 上界：

```js
const N = 4, GAP = 8
const triggerDistance = computed(() => {
  const col = hLeft >= hRight ? left : right      // 底部 = 较高列
  const last = col.slice(-N)
  if (!last.length) return 0                       // 空/短列表兜底，避免负 rootMargin
  return last.reduce((s, it) => s + HEIGHT[it.size], 0) + Math.max(0, last.length - 1) * GAP
})
```

- 均匀分布下该值 ≈ 860px（vs 固定 1480px），减少约 42% 的过早预取；连续 4 张 370 时仍自动扩到 1480 兜底。

### 7.3 组装 observer（rootMargin 不可变 → 追加后重建）

```js
let observer = null
function setupObserver(wrapEl) {
  observer?.disconnect()
  const root = resolveScrollRoot(wrapEl)          // null 或 body
  observer = new IntersectionObserver(onEnter, {
    root,                                         // null=视口 / body
    rootMargin: `0px 0px ${triggerDistance.value}px 0px`,
  })
  observer.observe(sentinelEl)
}

function onEnter(entries) {
  if (entries[0].isIntersecting) loadMore()
}

function loadMore() {
  if (loading.value || finished.value) return
  loading.value = true
  const batch = genBatch(BATCH)
  items.value.push(...batch)
  loading.value = false
  if (batch.length < BATCH) finished.value = true   // 数据源耗尽即到底，别硬编码 TOTAL
  nextTick(() => fillUntilCovered(wrapEl))   // 首屏铺满兜底
}

// 触发距离 = 卡片高度 + 列模式（单/双）决定，任一变化都重建 observer
watch(triggerDistance, () => setupObserver(wrapEl))
```

- **`rootMargin` 构造后不可改** → 用 `watch(triggerDistance)` 统一重建：追加一批（末 4 张变）或列模式切换（单↔双）都会触发；1 批 = 重建 1 次，代价可忽略。
- **不采用**「固定大 margin + 回调里二次算距离」：IO 的 `threshold` 只在交叉比跨过阈值时触发，默认 `[0]` 进去后不滚到退出就不会再 fire，会漏掉更接近的那次。
- **初始化时序**：`onMounted` 里 `setupColumns()` + `loadMore()` 即可，**无需显式调 `setupObserver`**——`loadMore` push 首批后 `triggerDistance` 变化，`watch(triggerDistance)` 自动触发 `setupObserver`；此时 `sentinelEl` 已在初始渲染中挂载（`onMounted` 在挂载后运行），非 null。`watch` 默认 `flush:'pre'`，若在 `setup()` 里同步 push 首批，哨兵 ref 仍是 null，`observe(null)` 会抛错（`setupObserver` 内部已做 `if (!sentinelEl) return` 兜底）。

### 7.4 加载锁 + 填满兜底

```js
function fillUntilCovered(wrapEl) {
  const scroller = resolveScrollRoot(wrapEl)
  const vh = scroller ? scroller.clientHeight : window.innerHeight
  const sh = scroller ? scroller.scrollHeight : document.documentElement.scrollHeight
  if (sh <= vh) loadMore()      // 内容未铺满视口（极少见）→ 继续填，防止 IO 死锁
}
```

- 本场景 `3000 > 600`，基本恒不触发，仅作安全网（如超大屏/大字体导致首屏 10 个未填满时，哨兵始终在视口内、IO 不会再次 fire）。

### 7.5 图片懒加载解耦

- 卡片 `<img loading="lazy">` + 固定尺寸占位，**「提前挂载 10 个卡片 DOM」≠「提前拉图片」**，图片等自身滚近视口才请求，过度预取基本不花流量。

## 8. 屏幕翻转支持

- **`matchMedia('(max-width:600px)')` 的 `change` 是列模式唯一真相源**（与 CSS 媒体查询同坐标系；`window.innerWidth` 含滚动条、会略偏，别混用）。
- 翻转/折叠跨过 600px → `change` 触发 → `isNarrow` 变化 → 重跑列拆分（§6.2）。
- **不要在 `resize` / `visualViewport.resize` 上做重锚定或重建 observer**：`visualViewport.resize` 在 iOS 滚动收起地址栏时高频触发，挂重逻辑是性能坑。`resize` 仅作旧浏览器兜底，且只在「列数真的变了」时才重排。
- `orientationchange`（已废弃）仅作旧 WebView 兜底。

### 8.1 双列 ↔ 单列 双向都要处理

翻转会跨越 600px 断点，两个方向都可能发生。**双列 → 单列**尤其要处理四点：

1. **列数重排**：所有卡片并入单列，`isNarrow` 变化触发 §6.2 重跑。
2. **触发距离公式天然覆盖**：单列时右列为空，`hLeft >= hRight` 恒成立，`triggerDistance` 自动退化为「单列最后 4 张高度和」，无需分支。
3. **哨兵位置**：哨兵在列容器之后（普通流），单列/双列都落在内容底部，无需移动。
4. **滚动锚点（关键，已实现为 `useScrollAnchor.js`）**：单列内容高度约翻倍，而 `scrollTop` 是像素值，重排后同一像素会落到不同内容上（用户「跳」到无关卡片）。记录翻转前视口顶部那张卡，重排后滚回：

```js
// 翻转前（断点变化、尚未重排，watch flush 'pre' 内同步捕获）
const anchorId = findFirstVisibleCard()          // 返回视口顶部那张卡的 id（按 rect.top 找，见下）

// 翻转后（重排完成，nextTick 内恢复）
nextTick(() => {
  const el = wrapEl.querySelector(`[data-id="${anchorId}"]`)
  if (el) {
    // 用 getBoundingClientRect 差值，别用 offsetTop（offsetTop 相对 offsetParent，不是滚动容器）
    const scrollerTop = scroller ? scroller.getBoundingClientRect().top : 0
    if (scroller) scroller.scrollTop += el.getBoundingClientRect().top - scrollerTop
    else window.scrollTo(0, window.scrollY + el.getBoundingClientRect().top - scrollerTop)
  }
})
```

> 若产品对翻转后的位置不敏感，可省略锚点保留、接受「回到相近位置」；但必须知道单列会让内容高度突变，不能假设浏览器自动保持。

- **时序**：锚点必须在**重排之前**同步捕获——用 `watch(isNarrow)`（默认 `flush:'pre'`，此刻 `isNarrow` 已赋新值但 DOM 仍是旧布局、Vue 重排是异步 flush）里捕获，否则捕获到的是新布局。
- **竞态**：折叠动画可能短时间多次跨过 600px，产生多个待恢复的锚点 → 只保留最新一个，丢弃/取消之前的恢复（用一个 `anchorRef` 覆盖，恢复前再比对 id）。
- **`cardElById` 机制**：卡片根元素挂 `data-id`，实现为 `wrapEl.querySelector('[data-id="…"]')`（id 为自增整数，无需转义）；`findFirstVisibleCard` 必须按 `getBoundingClientRect().top` 找视觉顶部那张卡——grid 下 DOM 顺序 ≠ 视觉顺序，不能按 DOM 顺序取第一个。

### 8.2 几何量重锚定

- 翻转后 `body.clientHeight` 可能变化（横屏高度变小），但 **`rootMargin` 只由卡片高度 + 列模式决定，与 body 高度无关**，横屏高度变化**不需要**重建 observer。
- 只有**列模式切换**（单↔双）才改变 `triggerDistance` → 由 §7.3 的 `watch(triggerDistance)` 自动重建；滚动根本身不变（滚动容器始终是同一个）。
- 翻转后保留已加载数据：不重置、不重复请求，只重排布局。

### 8.3 折叠屏特有

- **铰链 / 安全区**：展开后若内容会顶到铰链或被遮挡，用 `env(safe-area-inset-left/right)` 给容器留边距（`viewport-fit=cover` 时生效）。
- **展开/折叠动画会反复跨过 600px** → `change` 多次触发；列拆分与 observer 重建都需幂等（见 §8.1 竞态）。
- **展开宽度若仅略超 600px**（如 610px），双列每列约 290px，需确认卡片在该宽度下不显拥挤，必要时上调断点或设最小列宽。

## 9. 边界情况与性能

- **防重复触发**：`loading` 标志 + 请求间加锁；observer 回调幂等。
- **翻转导致列数变化**：只重排布局、不改变已加载数据，避免数据错乱。
- **图片懒加载**：`loading="lazy"` + 固定尺寸占位，减少流量。
- **overflow 提升陷阱**：滚动根运行时探测（§7.1），兼容 body 滚 / viewport 滚两种情形。
- **虚拟列表（可选优化）**：若后续单页卡片量极大，再引入虚拟滚动；本需求分批无限加载即可，暂不引入。
- **离线兜底**：图片 `onerror` 回退到纯色背景块，保证布局高度不塌。
